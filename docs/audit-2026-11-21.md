## 3. Honesty repairs

1. Vitals entries: removed the path that attached canned clinical staging to
   manual self-reported measurements. Manual entries now carry sourceType
   'manual' and no clinical interpretation. v0.3.0–v0.3.7 APKs still contain the
   old path — localStorage entries written by those builds are provenance
   suspects, not proven fabrications; no stored data was deleted or relabeled.
2. Fake AI-scan delays (fixed 600/700 ms setTimeouts) removed from the patient
   portal. Operations report their real outcome immediately.
3. Sample voice alert labeled at the control ("Play sample alert (synthetic
   script)"). Verified: no Notification API, push, scheduling or send exists in
   that flow; it is local playback only.
4. Emergency flows: already carried explicit labeling — "SIMULATION READY — NO
   DISPATCH" / "SIMULATION ACTIVE — PREVIEW ONLY" badge, per-step "No ambulance
   was dispatched; call 112/108" disclaimers, safety-bound AI narrator
   instructions. Verified tonight; no changes needed.
5. OCR result framing: the scanner states "No exact dictionary candidate —
   inspect extracted text" with an "UNVERIFIED OCR CANDIDATE" badge when text is
   garbled, and prompts the user to verify ingredient, strength and release
   form. Tonight's evidence proves progress + error-safe behavior, not
   extraction accuracy.

## 4. Animation behavior vs the user's rule

Rule: animations start with the operation, run while actually pending,
transition at the real result; no artificial minimums; no repeated splash.

| Flow | State | Evidence |
|---|---|---|
| Splash | Dismisses at first paint (245 ms), tap-skip kept | accept-verify.mjs |
| Prescription OCR | Measured progress while WASM runs | ocr-pending-to-result.mp4 |
| Acoustic analysis (YAMNet) | Real worker busy state + honest timeout | static review |
| OPD scribe | Real recording timer + VU | static review |
| Voice assistant | PARTIAL: VU real on physical mic; ambient-sim mode is explicitly labeled demo | code + UI labels |
| Emergency simulation | Labeled simulation motion (see §3.4) | code + UI labels |
| Synchronous actions (upload preview, search filter, FHIR export, settings save, vitals save) | No pending animation — result appears at true completion. By design; no decorative waits added | code review |
| Static icons (Doctor, Patient, Languages, Notifications bell, Logout, etc.) | No animation exists; adding decorative motion is a product decision not taken | — |

Recorded as PARTIAL reference coverage, not full completion.

## 5. Accessibility & i18n

- Vitals form: react-hook-form uncontrolled integration; invalid submit focuses
  the first error (shouldFocus); per-field aria-describedby errors.
- All validation messages come from i18n keys; dictionary-parity test enforces
  100% key completeness across en/te/hi/ta/kn/mr.
- Global rule `body:has(.modal-overlay) .m-assistant { display: none }` fixes
  the assistant launcher covering open modals (found by hit-testing audit).
- Dark-panel contrast repaired in the scanner: privacy badge (was dark teal on
  dark), token-panel heading and source badge now light on navy. Sweep of all
  #065F46/#00A896 uses found no other dark-on-dark cases.
